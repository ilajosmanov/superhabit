# server

The Cloudflare Worker the app talks to: Hono on Workers, D1 (placed in eastern North America, near the
US and the UK), Better Auth through Drizzle. See the Data architecture doc, section 4, and "The server"
in CODING_STANDARDS.md for the layers.

| Folder / file       | Holds                                                                                                                     |
| ------------------- | ------------------------------------------------------------------------------------------------------------------------- |
| `src/index.ts`      | the Worker: mounts the routes, runs the hourly Cron                                                                       |
| `src/env.ts`        | the bindings, vars and secrets the Worker gets; Hono route types                                                          |
| `src/auth/`         | Better Auth (Google ID tokens, year-long sessions), its routes, `signedIn`, `signInLimit`                                 |
| `src/account/`      | `GET /me`, `DELETE /account`, the `/delete` web page, the purge of deleted accounts                                       |
| `src/sync/`         | `POST /sync`: the phones' outbox rows (`changes.ts` is their shape), kept once by id; the changes log; `GET /sync`: pulls |
| `src/consents/`     | `PUT /consent`: one consent in force per kind, every grant kept as proof                                                  |
| `src/traces/`       | `PUT /traces/<set>`: shared traces into R2 (`header.ts` reads a file's header); their deletion and the daily sweep        |
| `src/leagues/`      | `GET /leaderboard`, `PUT /leaderboard/visibility`; points (`points.ts`), boards of 30, the weekly close                   |
| `src/db/`           | tables (`schema.ts`; Better Auth's generated `auth-schema.ts`), `open()`                                                  |
| `src/__fixtures__/` | the test harness: the Worker on a local D1, test-signed Google tokens                                                     |
| `migrations/`       | generated by drizzle-kit; commit them                                                                                     |
| `wrangler.jsonc`    | the Worker: D1 binding `DB`, R2 binding `TRACES`, rate limiter, vars, the Cron                                            |

## Routes

- `GET /health`: up, and the database answers.
- `/api/auth/*`: Better Auth; sign-in attempts (POSTs) are limited to 30 a minute per IP. The phone signs in with
  `POST /api/auth/sign-in/social` `{ provider: 'google', idToken: { token } }` (audience: our Web client
  ID) and calls `GET /api/auth/get-session` at launch: only that renews the session (once a day).
- `GET /me`: id, name, image (from Google) and the consents in force.
- `PUT /consent` `{ kind: 'traces' | 'video', policyVersion, granted }`. Withdrawing traces deletes the
  account's shared traces.
- `PUT /traces/<set>`: a set's `.sht` file, at most 8 MB, kept in R2 (`superhabit-traces`, eastern North
  America) at `traces/<user>/<set>.sht` with a `traces` row, written first so every file has one. Taken
  only while the account shares (else 403), for a set it has synced (else 409), from a whole gzip whose
  header names that set and a `traces@` consent at capture (else 422). Consent is checked again after the
  file lands; a withdrawal in between deletes it. A repeat writes the same file.
- `DELETE /account`: signs every phone out at once; the same Google account comes back as a new user.
- `GET /delete`: the same deletion from a browser (Google Play asks for one), rendered on the server
  (`account/delete-page.tsx`, Hono JSX) with plain forms and no script. `POST /delete/google` starts
  Google's redirect sign-in (`/api/auth/callback/google`, registered on the Web client; the same limit),
  `POST /delete` deletes the account the page showed (a form from before switching accounts deletes
  nothing), `POST /delete/sign-out` is "Not me". The posts take only the page's own origin; the page
  can't be framed.
- `POST /sync` `{ changes: [{ entity, entityId, op, payload }] }`, at most 50 and 1 MB: the phone's outbox
  rows, oldest first, kept in one transaction. Facts (versions, runs, workouts with their sets, freezes)
  are kept as first sent, so a repeat changes nothing. Only the account's own rows change: a run's end
  once (the first leave stands), a challenge's current version to the newest version the server took (a
  resent old edit doesn't undo a newer one). Answers `{ results }`, one `{ ok: true }` or
  `{ ok: false, reason }` per change. Every row written moves to the end of the `changes` log, which pulls
  read; an entry can name a row that doesn't exist (an edit of someone else's challenge), so pulls skip it.
- `GET /sync?after=<cursor>` (0 for everything): the account's rows written since, 50 log entries a page,
  oldest first, each as the phone keeps it (a challenge with its `owner`, a workout with its `sets`):
  `{ rows: [{ entity, row }], cursor, more }`. An edited challenge or left run comes again, after rows
  that point at it, so only a whole pull is complete.
- `GET /leaderboard`: your board this week, putting you on one first: `{ week, endsAt, league, up, down,
  visible, rows: [{ rank, you, name, image, points }] }`. Weeks run Monday to Monday, 00:00 UTC. Each
  league (Bronze, Silver, Gold) splits into boards of up to 30; a newcomer starts in Bronze. Points count
  live from synced sets that ended in the week: effort (MET × seconds of work, one squat = 1 point) up to
  each set's goal, plus 5% for each streak day before, up to 50%. Others are named (first name, last
  initial) only if they chose to be seen. 503 for a newcomer to the week until last week has closed.
- `PUT /leaderboard/visibility` `{ visible }`: whether your board sees your name and photo. No choice yet
  means hidden.
- Cron, hourly: closes last week if it isn't yet (Monday's first run; a failed close is finished an hour
  later). The close puts whoever trained on a board, ranks each board (the top `min(5, n/3)` with points
  move up, as many at the bottom move down), puts whoever scored on next week's boards, and records the
  week closed in `league_closes`: a workout synced later doesn't reopen it. Then it puts whoever trained
  this week on a board. At 00:00 UTC also: deletes the traces of accounts that no longer share or no
  longer exist, and what deleted accounts left: consents, every synced row and their leagues (all
  deleted accounts each run, so a sync that raced its deletion is caught).

## Running it

Wrangler and drizzle-kit read `CLOUDFLARE_API_TOKEN` and `CLOUDFLARE_ACCOUNT_ID` from the repo's
git-ignored `cloudflare.env`; load it first: `set -a; . ../cloudflare.env; set +a`.

- `vp run dev`: the Worker locally, with a local D1.
- `vp run deploy`: to https://superhabit.cloudflare-putt001.workers.dev.
- `vp exec drizzle-kit generate` after a schema change, then `vp exec drizzle-kit migrate` for the D1 in
  Cloudflare.
- Secrets (`wrangler secret put`): `BETTER_AUTH_SECRET`; `GOOGLE_CLIENT_SECRET` (from `google.env`), which
  only the web deletion page's browser sign-in (4.5) will use.
- Tests run with the root `vp test`.
- After changing Better Auth's plugins, regenerate `src/db/auth-schema.ts`: `npx auth generate --config
  <file> --output src/db/auth-schema.ts`, with a throwaway config building `betterAuth` with the same plugins.
